## 1. 專案概述

本工具為金融監督管理委員會（FSC）電子支付業務統計資料的**查詢、管理與更新平台**，整合了以下資料來源：

| 資料來源 | 說明 | 更新方式 |
|---------|------|---------|
| ebank.banking.gov.tw | 各機構月度申報資料（27 種報表） | JS 腳本爬取 / Python Playwright 爬取 |
| banking.gov.tw 公開揭露 | 全業者摘要統計表（ZIP→Excel） | 手動下載後執行 `import_disclosure_zip.py` |
| 行政院月票方案 | 月票交易統計 | Excel 手動上傳 |

## 3. 檔案說明

### 3.1 `web_app.py`（Flask 主應用，129 KB）

系統最核心的檔案，包含所有 API 端點與前端邏輯。

**主要功能區塊：**

| 功能 | 路由 / 函式 | 說明 |
|------|------------|------|
| 首頁 | `GET /` | 渲染 `index.html` |
| 資料表清單 | `GET /api/tables` | 回傳所有資料表代碼與描述 |
| 資料瀏覽 | `GET /api/browse/<code>` | 分頁查詢指定資料表，支援篩選機構、年月 |
| 趨勢查詢 | `GET /api/trend/<code>` | 指定欄位的時間序列資料（用於折線圖） |
| 單月比較 | `GET /api/compare/<code>` | 指定月份各機構橫向比較 |
| 匯出 CSV | `GET /api/export/<code>/csv` | 下載指定表的 CSV 報表 |
| 匯出 Excel | `GET /api/export/<code>/excel` | 下載指定表的 Excel 報表 |
| 上傳 JSON | `POST /api/upload` | 上傳 `ebank_update_*.json` 並自動匯入 DB |
| 全業者統計 | `GET /api/industry_stats` | 全業者摘要統計查詢（趨勢/排行/比較） |
| 月票統計 | `GET /api/monthly_pass` | 行政院月票方案交易統計 |
| Dashboard | `GET /api/dashboard` | 首頁 KPI 摘要卡片資料 |
| 欄位標籤 | `GET /api/labels/<code>` | 回傳指定表的中文欄位說明 |

**欄位標籤系統：**  
`FULL_COL_LABELS` 字典收錄所有 27 張報表的完整中文欄位對應，欄位代碼（如 `_3000A`）→ 中文說明（如「電支帳戶戶數總計」）。

**多層次表頭：**  
`TABLE_STRUCTURE` 字典定義 EP007W、EP008W、EP014W 等複雜表格的群組化顯示結構，前端可渲染跨欄標題。

### 3.2 `build_database.py`（資料庫初始化）

從 JSON 資料源重建完整 SQLite 資料庫。

**執行時機：** 全量重建時使用（首次部署或資料修復）

**流程：**
1. 載入 `ebank_all_data_final.json`（主資料）
2. 載入 `ebank_all_data.json`（補充歷史月份）
3. 對 `SUPPLEMENT_TABLES` 中的特定表，補入 old 資料中 final 沒有的月份
4. JSON-level 去重後動態建表並插入
5. 從 `電子支付機構_全業者統計.csv` 建立「全業者統計」表
6. 從 `WB032W_申訴服務專線維護.csv` 建立 `WB032W` 表
7. 建立 `_metadata` 表記錄各表描述

```bash
python3 build_database.py
```

---

### 3.3 `merge_updates.py`（增量合併）

將每次爬取的 `ebank_update_*.json` 合併成 `build_database.py` 所需的格式。

**執行時機：** 每次爬取新資料後，在重建資料庫前執行

**流程：**
1. 讀取所有 `ebank_update_*.json`（本次抓取結果）
2. 讀取 `ebank_json/JSON/ebank_*.json`（per-item 歷史檔，補充更早月份）
3. 以 `(yr, mn, sn)` 為去重 key，新資料優先
4. 輸出 `ebank_all_data_final.json` 與 `ebank_all_data.json`

```bash
python3 merge_updates.py
```

---

### 3.4 `migrate_database.py`（資料庫驗證遷移）

安全地驗證並替換資料庫，確保無資料遺失。

**流程：**
1. 備份現有 `fsc_ebank.db` → `fsc_ebank_backup.db`
2. 使用 SQLite backup API 建立 `fsc_ebank_new.db`
3. 逐表比對列數、欄位名稱、SHA-256 hash
4. 驗證全部通過後，以新庫替換舊庫

```bash
python3 migrate_database.py
```

### 3.5 `import_disclosure_zip.py`（公開揭露 ZIP 匯入）

解析金管會公開揭露頁面下載的 ZIP 檔（`BB-YYMM_電子支付帳戶重要資訊揭露.zip`），寫入資料庫的「全業者統計」表。

**ZIP 格式：**
- 每個 ZIP 內含 `YYMM_電子支付帳戶重要資訊揭露.xlsx`
- Excel 第 3 行：資料月份（`115年1月`）
- Excel 第 6 行起：各機構資料

**欄位對應：**

| Excel 欄 | 資料庫欄位 |
|---------|-----------|
| 電子支付機構名稱 | 機構名稱 |
| 使用者人數 | 使用者人數 |
| 當月代理收付實質交易款項金額 | 代理收付金額_千元 |
| 當月辦理國內外小額匯兌金額 | 移轉匯兌金額_千元 |
| 當月收受儲值款項金額 | 收受儲值金額_千元 |
| 儲值款項餘額 | 儲值餘額_千元 |
| 代理收付款項餘額 | 代理收付餘額_千元 |
| 合計 | 各類餘額合計_千元 |

**用法：**
```bash
# 指定檔案
python3 import_disclosure_zip.py BB-1151_*.zip BB-1152_*.zip

# 自動掃描目錄下所有 BB-*.zip
python3 import_disclosure_zip.py
```

**冪等特性：** 重複執行會先刪除同月份舊資料再重新插入，不會產生重複。

### 3.6 `ebank_monthly_updater.py`（Python Playwright 爬蟲）

自動登入 `ebank.banking.gov.tw` 並抓取月度申報資料。

**特點：**
- 以 `.ebank_updater_state.json` 記錄上次抓取年月，每次只抓新月份
- 支援 27 種報表的全自動巡覽
- 逐筆進入明細頁解析欄位（包含 rowspan/colspan 複雜表格）
- 失敗自動重試（最多 2 次）
- 輸出 `ebank_update_<yr>_<mn>.json`

**命令列參數：**
```bash
python3 ebank_monthly_updater.py              # 一般執行
python3 ebank_monthly_updater.py --reset      # 清除記錄，重新抓取
python3 ebank_monthly_updater.py --months 6   # 首次執行抓最近 6 個月
python3 ebank_monthly_updater.py --dry-run    # 僅預覽不執行
python3 ebank_monthly_updater.py --output ./data  # 指定輸出目錄
```

## 5. 核心功能模組

### 5.1 資料瀏覽（Browse）

- 支援所有 27 種申報報表 + 全業者統計
- 篩選條件：機構名稱、年份、月份
- 分頁顯示（每頁 50 筆）
- 複雜表格支援多層次欄位標題（GroupHeader）

### 5.2 趨勢分析（Trend）

- 選擇任意數值欄位，繪製時間序列折線圖
- 可多機構疊加比較
- 支援全業者統計的趨勢查詢

### 5.3 橫向比較（Compare）

- 選擇特定月份，比較各機構同一指標
- 以長條圖或表格呈現排名

### 5.4 全業者統計儀表板

- 來源：`全業者統計` 資料表
- 資料期間：107年4月 ～ 115年3月（最新）
- 功能：使用者人數趨勢、代理收付金額趨勢、各機構份額比較

### 5.5 JSON 上傳匯入

- 接受 `ebank_update_*.json` 格式（由爬蟲產出）
- 自動去重（以 yr/mn/sn 為 key）
- 記錄於 `_import_log` 表避免重複匯入
- 支援單檔 / 多檔批次上傳

### 5.6 CSV / Excel 匯出

- 可對任意資料表匯出
- CSV：UTF-8 with BOM（Excel 相容）
- Excel：使用 `openpyxl` 產生，含欄位中文標題

## 6. 資料更新流程

### 流程 A：ebank 申報資料月度更新

```
方法一（Python Playwright）：
python3 ebank_monthly_updater.py
    ↓ 產出 ebank_update_<yr>_<mn>.json

方法二（Chrome DevTools）：
登入 ebank → 執行 ebank_monthly_updater.js
    ↓ 下載 ebank_update_<yr>_<mn>.json

共同後續步驟：
python3 merge_updates.py          # 合併 JSON
    ↓ 更新 ebank_all_data_final.json

python3 build_database.py         # 重建資料庫
    ↓ 產出新 fsc_ebank.db

（選用）python3 migrate_database.py  # 驗證資料一致性
```

### 流程 B：公開揭露統計資料更新

```
1. 至 https://www.banking.gov.tw/ch/home.jsp?id=591&...
   下載最新月份的 ZIP 檔（BB-115XX_電子支付帳戶重要資訊揭露.zip）

2. 將 ZIP 放到 FSCWEB/ 目錄

3. python3 import_disclosure_zip.py
   （自動掃描所有 BB-*.zip 並寫入資料庫）

注意：此流程直接寫入 fsc_ebank.db，不影響 JSON 資料源
```

## 9. 常見問題

| 問題 | 原因 | 解法 |
|------|------|------|
| `ModuleNotFoundError: flask` | 預設 `python3` 是 conda 3.8 | 改用 `/opt/homebrew/bin/python3.12` |
| `SyntaxError: invalid escape sequence '\_'` | Python 3.12 將此升為 SyntaxError | 已修正（`'\\_%'` 雙反斜線）|
| 全業者統計無新資料 | ZIP 檔未放到 FSCWEB/ 目錄 | 執行 `import_disclosure_zip.py` 前確認檔案位置 |
| ebank 爬取全部逾時 | 未在 `/Frame` 主頁執行 | 確認已登入，且頁面為 Frame 首頁 |
| Cloudflare URL 每次不同 | quick Tunnel 特性 | 使用付費 Cloudflare 帳號建立固定 Tunnel |
| DB 更新後 Web 未反映 | Flask 直接讀 DB，需重啟 | `Ctrl+C` 後重新執行 `./start.sh` |
